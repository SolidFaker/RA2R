> 用途：MIT 洁净室自研 C++20 引擎（RA2R）软件光栅化体素 PoC 的格式参考。
> 本文只记录**事实与规格**（字段偏移、字节序、编码含义），不包含任何第三方代码实现。

## 1. VXL（Voxel）格式

### 1.0 文件总览

```
+------------------+  0x0000
| 主头 (Header)     |  802 字节（magic + 计数 + 内嵌 256 色调色板）
+------------------+  0x0322
| Section 头       |  n_limbs × 28 字节
+------------------+
| Section Body     |  body_size 字节（所有 section 的 span 数据打包于此）
+------------------+
| Section Tailer   |  n_limbs × 92 字节
+------------------+
```

- 头部的 `body_size` 给出 Body 区总字节数；`802 + 28×n_limbs + body_size` 即 Tailer 区起点。
- 每个 section 的 Body 内容只能通过该 section 的 Tailer 内偏移**按引用**访问（不保证顺序与 section 头一一对应，虽然官方资产总是递增对应）。

### 1.0.1 一个单位由多个 VXL 组成（命名约定）

原版把"车体/底座 + 炮塔 + 炮管"拆成**独立 VXL 文件**，靠文件名约定配对（rulesmd/artmd 里没有键指向炮塔/炮管）：

| 部件 | 文件名 | 例子 | 实测坐标关系 |
|---|---|---|---|
| 车体 / 建筑本体 | `<Image>.VXL` | `GTNK.VXL`（z 0.6–12.4） | 原点 = 底盘中心地面 |
| 炮塔 | `<Image>TUR.VXL` | `GTNKTUR.VXL`（z 11.6–18.5）、`GTGCANTUR.VXL` | 与车体**同一坐标系**（炮塔 z 从车体顶部起） |
| 炮管 | `<Image>BARL.VXL` | `GTNKBARL.VXL`（z 11.7–15.3）、`GTGCANBARL.VXL`（x 21.5–74.8） | 同上，从炮塔前端向 +x 延伸 |

- 建筑：`TurretAnim=<名>` 给炮塔模型名（如 `GTGCANTUR`），炮管仍按 **建筑类型/美术名 + `BARL`**（`GTGCAN` → `GTGCANBARL`）。
- 全库共 14 个 `*BARL.VXL`（坦克 1TNK/2TNK/3TNK/4TNK/GTNK/HTNK/LTNK/MTNK/RTNK/HTK、ART2/ARTY、MMCH、GTGCAN）。
- **必须把同一单位的多个部件放进同一次光栅化、共享深度缓冲**（`render::rasterize_voxel_parts`）；分别渲染再叠加会出现炮管与炮塔互相穿插，或（漏掉时）坦克只有底盘、巨炮没有炮管。
- 炮塔/炮管的相对位置**只由模型坐标决定**，不需要额外偏移：`GTGCANBARL` 的 x 从 21.5 起，正好接在 `GTGCANTUR` 的 x 上限 25.3 处。

### 1.1 主头（Header，802 字节）

| 偏移 | 字段 | 类型 | 含义 |
|------|------|------|------|
| `0x00` | `id` | `char[16]` | 魔数 `"Voxel Animation"`（ASCIIZ，后补 `\0`）。**注**：格式俗名常写作 "Voxel Section"，但实际魔数字节是 **"Voxel Animation"**（XCC `vxl_id`、OpenRA `StartsWith("Voxel Animation")`、XHP 规格三者一致）。TS 与 RA2 均用此魔数 |
| `0x10` | `unknown` | `int32` | 恒为 `1`。XHP 推测可能是「动画帧数」占位（被砍功能），含义**待验证** |
| `0x14` | `n_limbs` | `uint32` | section（limb）数量 |
| `0x18` | `n_limbs2` | `uint32` | 恒等于 `n_limbs`（tailer 数量；两者在官方文件中始终相同） |
| `0x1C` | `body_size` | `uint32` | 所有 section 的 Body 区总字节数 |
| `0x20` | `unknown2` | `int16` | 恒为 `0x1F10`（版本/魔数，含义**待验证**） |
| `0x22` | `palette` | `byte[256][3]` | 内嵌 256 色 RGB 调色板，768 字节，**每通道 8-bit（0–255）**，见 §3.3 |

> **偏移分歧**：cnc-formats 把 `0x20` 拆成两个 `u16`（`start_palette_remap`/`end_palette_remap`），使调色板落在 `0x24`、头大小算成 804；而 XCC 的 `#pragma pack(1)` 结构体、OpenRA 的 `Seek(770)`、XHP 规格三者一致地把 `0x20` 当作单个 `int16`，调色板在 `0x22`、头大小 **802**。本文按 802/`0x22` 记；cnc-formats 的 2 字节差异记为已知分歧（**待验证**）。

### 1.2 Section 头（Limb Header，28 字节 × n_limbs）

| 偏移 | 字段 | 类型 | 含义 |
|------|------|------|------|
| `0x00` | `name` | `char[16]` | section/limb 名（ASCIIZ，`\0` 后常有残留垃圾字节，忽略即可） |
| `0x10` | `section_i` | `int32` | limb 序号（通常递增） |
| `0x14` | `one` | `int32` | 恒为 `1` |
| `0x18` | `zero` | `int32` | 恒为 `0` |

### 1.3 Section Body（span 编码）

每个 section 的 Body 由三部分组成（偏移相对 Body 区起点）：

```
[ span_start 列表 ]  size_x × size_y 个 int32
[ span_end   列表 ]  size_x × size_y 个 int32
[ span 数据区     ]  变长字节流
```

| 部分 | 说明 |
|------|------|
| `span_start[]` | 第 `j` 列 span 数据在**span 数据区内**的字节偏移；空列 = `-1`（`0xFFFFFFFF`） |
| `span_end[]` | 第 `j` 列 span 数据的**末字节**偏移（`size = end - start + 1`）；空列 = `-1` |
| `span 数据` | 每个非空列是一串 run（见下） |

**列遍历顺序（x/y/z 循环顺序）** —— 这是软件光栅化的关键：

- 列索引 `j = x + size_x * y`，外层循环 `y`（0..size_y-1），内层循环 `x`（0..size_x-1），即 **x 变化最快、y 为外层**。
- 等价地：`x = j % size_x`，`y = j / size_x`（OpenRA 的 `VoxelMap[x,y]` 就是这么建的）。
- 在**每一列内部**，z 从 0 开始，靠 run 的「跳过计数」单调递增到 `size_z`，即 **z 沿 +z 方向顺序编码**。

**单个 run 的字节布局**（每列由 0 个或多个 run 组成，直到累计 z 达到 `size_z`）：

| 字节 | 含义 |
|------|------|
| 1 字节 | **SKIP**：本 run 前要跳过的空体素个数（z += SKIP） |
| 1 字节 | **COUNT**：本 run 内的体素个数 |
| `COUNT × 2` 字节 | 每个体素一对 `(color, normal)`，各 1 字节 |
| 1 字节 | **COUNT 的重复值**（冗余的「重复计数」，等于上面的 COUNT，解码时可跳过） |

> 注意：任务描述里的「每列 count 字节 + count×(color,normal) 对」省略了**前导 SKIP 字节**与**末尾的重复 COUNT 字节**。完整 layout 为 `SKIP | COUNT | COUNT×(color,normal) | COUNT`。

**每体素 2 字节的确切含义**：

| 字节 | 字段 | 含义 |
|------|------|------|
| 第 1 字节 | `color` | 调色板索引（0–255），指向 VXL 内嵌调色板（或游戏运行时调色板）。`0` 通常视为透明/空（正常资产中不存储 `color=0` 的体素） |
| 第 2 字节 | `normal` | **法线索引**，指向法线方向表（见 §1.6）：RA2 为 0–243（244 条），TS 为 0–35（36 条） |

**解码伪流程**（仅描述算法，非代码）：

```
for y in 0..size_y:
  for x in 0..size_x:
    j = x + size_x*y
    if span_start[j] == -1: continue          # 空列
    z = 0
    while z < size_z:
      z += SKIP                                # 读 1 字节
      COUNT = 下一字节
      for k in 0..COUNT:
        color  = 下一字节
        normal = 下一字节
        voxel(x, y, z) = (color, normal)
        z += 1
      跳过 1 字节（重复 COUNT）
```

末尾 run 若 `z + SKIP == size_z` 且 COUNT=0，是一个合法的「结束标记」（XCC 写出 `cz - z, 0, 0`），不会产生体素。

### 1.4 Section Tailer（92 字节 × n_limbs）

| 偏移 | 字段 | 类型 | 含义 |
|------|------|------|------|
| `0x00` | `span_start_off` | `int32` | 相对 Body 区起点的 span_start 列表偏移 |
| `0x04` | `span_end_off` | `int32` | 相对 Body 区起点的 span_end 列表偏移 |
| `0x08` | `span_data_off` | `int32` | 相对 Body 区起点的 span 数据区偏移 |
| `0x0C` | `det`/`scale` | `float32` | 缩放/行列式值（OpenRA 用作 scale，XCC 名 `scale`，cnc-formats 名 `det`） |
| `0x10` | `transform` | `float32[3][4]` | 3×4 基础变换（行主序：3 行 × 4 列，前 3 列为旋转/缩放，第 4 列为平移），共 48 字节。多数加载器忽略（动画由 HVA 提供），**含义待验证** |
| `0x40` | `min` | `float32[3]` | AABB 最小角 `(x_min, y_min, z_min)` |
| `0x4C` | `max` | `float32[3]` | AABB 最大角 `(x_max, y_max, z_max)` |
| `0x58` | `size_x` | `uint8` | 体素网格 X 尺寸 |
| `0x59` | `size_y` | `uint8` | 体素网格 Y 尺寸 |
| `0x5A` | `size_z` | `uint8` | 体素网格 Z 尺寸 |
| `0x5B` | `normals_type` | `uint8` | 法线类型：`2`=TiberianSun，`4`=RedAlert2（OpenRA 枚举 `NormalType`）。精确语义**待验证** |

> 历史注记：XHP 旧规格把 `0x0C`–`0x4B` 记作 `float transform[4][4]`、`0x4C`–`0x57` 记作 `float scale[3]`。现代实现（OpenRA/XCC/cnc-formats）统一为「det + 3×4 变换 + min/max 包围盒」，本文采用后者（已在真实 RA2 资产上被 OpenRA 验证）。

## 2. HVA（Voxel Animation）格式

HVA 为每个 section 的**每一帧**提供 3×4 变换矩阵（旋转 + 平移），与 VXL 同名配对使用。

```
+------------------+  0x00
| 头 (Header)       |  24 字节
+------------------+  0x18
| Section 名        |  n_sections × 16 字节
+------------------+
| 变换矩阵          |  n_frames × n_sections × 48 字节
+------------------+
```

### 2.1 头（24 字节）

| 偏移 | 字段 | 类型 | 含义 |
|------|------|------|------|
| `0x00` | `id` | `char[16]` | 文件名/标识字段（null 补 0）。**无严格 magic**；常为模型名或空白（XCC 写出 `"NONE"`）。是否约定 `"HVA"` 前缀**待验证** |
| `0x10` | `n_frames` | `uint32` | 动画帧数 |
| `0x14` | `n_sections` | `uint32` | section 数 |

### 2.2 Section 名

- `n_sections × 16` 字节，每项为 ASCIIZ section 名（与 VXL 的 section 名对应）。

### 2.3 变换矩阵（每帧每 section）

| 项 | 值 |
|----|----|
| 大小 | 每个矩阵 48 字节 = 12 × `float32`（小端 IEEE 754） |
| 排列顺序 | **frame-major**：先帧后 section。`index = frame × n_sections + section`（OpenRA 与 cnc-formats 一致） |
| 矩阵含义 | 12 个 float 构成 **3×4 矩阵（行主序，3 行 × 4 列）**：前 3 列为 3×3 旋转/缩放部分，第 4 列为平移 `(tx, ty, tz)` |

磁盘 12 个 float（`f0..f11`）的两种等价读法：

```
# 读法 A：3 行 × 4 列，行主序（cnc-formats / XCC 的 float[3][4]）
row0 = [ f0  f1  f2  f3 ]      # 平移在 f3
row1 = [ f4  f5  f6  f7 ]      #           f7
row2 = [ f8  f9 f10 f11 ]      #           f11

# 读法 B：列主序 4×4 的转置（OpenRA HvaReader 的做法，把文件矩阵转置进列主序）
col0 = (f0, f1, f2, f3) = (m00, m10, m20, tx)
col1 = (f4, f5, f6, f7) = (m01, m11, m21, ty)
col2 = (f8, f9, f10, f11)= (m02, m12, m22, tz)
```

即：**`f[r*4 + c]` 为矩阵第 r 行第 c 列**（第 c=3 列是平移）。OpenRA 内部按列主序存储，因此它把 `f3/f7/f11` 放在第 4 行当平移（转置关系）。

> **排列顺序冲突**：XCC `get_transform_matrix(section, frame)` 用 `(n_frames * section + frame)`（**section-major**），与 OpenRA/cnc-formats 的 **frame-major** 相反。OpenRA 在真实 RA2 资产上验证可用，cnc-formats 为 RA2 洁净室实现，二者一致，故本文取 **frame-major**；XCC 的 section-major 记为已知分歧（**待验证**）。

## 3. PAL（调色板）

> **重要区分（实测修正）**：本节标题的「PAL」指独立 `.pal` 文件（6-bit）；**VXL 主头内嵌的
> 768 字节调色板是 8-bit**（每通道 0–255），两者数值不同、换算也不同。见 §3.3。

### 3.1 二进制布局（768 字节）

| 项 | 值 |
|----|----|
| 结构 | 256 个表项 × 3 字节 `(R, G, B)`，共 768 字节，**无头、无 footer、无 magic** |
| 通道位深 | **每通道 6-bit，范围 0–63**（VGA DAC 寄存器位宽，即「18-bit 色」）。XCC 的 `is_valid()` 显式校验 `(r|g|b) & 0xC0 == 0` |
| 6→8 bit 换算 | `v << 2`（63 → 252，VGA DAC 硬件行为，cnc-formats）；或 `v * 255 / 63`（63 → 255，XCC `convert_palet_18_to_24`）。两种换算并存，写引擎时任选其一并保持一致 |

### 3.3 VXL 内嵌调色板是 8-bit（与 .PAL 不同）

VXL 主头 `0x22` 处的 768 字节调色板**已经**是 8-bit 值（0–255），**不要再 `<<2`**。
实测（`YAGGUN.VXL` 内嵌 vs `UNITURB.PAL`，同索引）：

| 索引 | VXL 内嵌 | UNITURB.PAL | 关系 |
|---|---|---|---|
| 13 | 87 | 21（→84 8-bit） | 内嵌 ≈ .PAL 值 ×4 |
| 15 | 255 | 63（→252） | 同上 |
| 20 | 195 | 48（→192） | 同上 |
| 16 | 255 | 63（→252） | 同上 |

即内嵌调色板是同一组颜色的 8-bit 版本。渲染体素时**直接取用内嵌值**（最多再乘光照系数）；
若沿用 `.PAL` 的 6-bit 约定再 `<<2`，整模会过曝（暗部拉白、炮管发白、层次丢失）。
| 8→6 bit 换算 | `v >> 2` |
| 索引 0 | 通常为透明/黑（部分工具置为品红 `255,0,255` 做透明键） |

### 3.2 JASC-PAL 文本变体

文本头 + 256 行十进制 RGB（**8-bit，0–255**；由 6-bit 值 `<<2` 或 `*255/63` 展开后写出）：

```
JASC-PAL
0100
256
R G B      # 索引 0
R G B      # 索引 1
...
R G B      # 索引 255
```

（来源：XCC `Cpal_file::extract_as_pal_jasc`，写出 `"JASC-PAL" / "0100" / "256"` 后按行 `R G B`。）

### 3.3 RA2 光照等级 / 阴影斜坡（简述）

RA2 为 8-bit 索引色，光照不改变 RGB 值，而是通过**调色板索引重映射（ramp/斜坡）**实现明暗：

1. **色斜坡（color ramp）**：调色板按「16 色一族」组织——每个基准色带一串逐级变暗的同色系变体。单位调色板（`unit*.pal` / `unittem.pal` 等）的常规结构：
   - 索引 `0`：透明/背景；
   - 索引 `1–15`：特效区（含阴影色、轮廓色等）；
   - 索引 `16–31`：**可换色（remap）区**（16 色，用于玩家/阵营换色）；
   - 索引 `32–255`：单位自身颜色，按 16 色 ramp 排布（1 个基准色 + 15 级渐暗）。
2. **方向光 + 法线**：体素用其 `normal` 索引查 §1.6 方向表得单位向量 `N`，与全局光方向 `L` 做 Lambert 点积 `max(0, N·L)`，得到该体素（面）的亮度系数。
3. **索引斜坡映射**：亮度系数与全局光照等级一起，把体素的 `color` 索引沿其所在 ramp 向更暗（阴影）端移动，选出实际绘制的调色板索引——即「阴影斜坡」。地面阴影（cast shadow）用单独阴影色/半透明斜坡。
4. 原版「如何把 法线·光方向 精确映射到具体索引」的算法**未公开**（XHP 旧规格明言「how the voxels are being shaded 未知」）。OpenRA 以着色器近似：`LightPitch=50°`、`LightYaw=240°`、环境光 `0.6`、漫反射 `0.4`，`color = ambient + diffuse·max(0, N·L)`（近似原版观感，**非逐位复刻**）。
5. 关于「32 级明暗」的精确实现（离散光级数、逐级斜坡表）**未能多源确认，标记待验证**；可确认的是 Chronoshift `PaletteClass::Adjust` 通过对黑调色板做线性插值实现「fading 渐暗」（`FadingShade` 表），这是 RA2 明暗斜坡的一种实现形式。

## 4. 法线索引表（软件光照关键）

## 5. 关键发现（调研结论）

1. **VXL span 遍历顺序**：列索引 `j = x + size_x*y`（**x 最快、y 外层**，z 沿 +z 由 SKIP/COUNT run 顺序推进），已由 XCC `extract_as_text`（`y` 外、`x` 内、`j++`）、OpenRA `VxlReader`（`x = i % size_x; y = i / size_x`）、XHP 规格三处交叉确认。每列 run 的**完整**布局是 `SKIP | COUNT | COUNT×(color,normal) | COUNT(重复)`，末尾那 1 个字节是 COUNT 的冗余重复（XHP 规格原话「same value as previous declaration」）。
2. **法线表来源**：完整 RA2（244 条）+ TS（36 条）方向表取自 **OpenRA `VoxelNormalsPalette.cs`**，其注释指向 **sleipnirstuff 论坛 t=8048 存档帖**（原版逆向成果）。RA2 表索引 0–243，末尾 240–243 为同一向量 `(-0.328188, 0.140251, 0.934143)` 填充；TS 表仅 36 条（TS 法线可能为约简集，**待验证**）。`normal` 字节上限与表长（244 vs 常被引用的 243/256）存在出入，**待验证**。
3. **魔数修正**：任务提示的 `'Voxel Section'` 其实是格式俗名；实际 16 字节魔数是 **`"Voxel Animation"`**（XCC `vxl_id`、OpenRA、XHP 规格三者一致）。主头共 **802 字节**（`0x20` 是单个 `int16 = 0x1F10`，调色板在 `0x22`）；cnc-formats 的 804/调色板 `0x24` 是 2 字节分歧，按 802 记。
4. **HVA 矩阵排列存在真实冲突**：OpenRA 与 cnc-formats 一致采用 **frame-major**（`frame×n_sections+section`），XCC 采用 section-major。取 frame-major（OpenRA 已在真实 RA2 资产上验证）；矩阵为 12 个 float32 LE，3×4（前 3 列旋转、第 4 列平移），OpenRA 读入时按列主序转置。
5. **PAL 是 6-bit，但 VXL 内嵌调色板是 8-bit**：独立 `.pal` 文件为 256×3=768 字节、每通道 **0–63（6-bit VGA DAC）**，6→8 bit 有 `<<2`（→252）与 `*255/63`（→255）两种换算并存（cnc-formats vs XCC），复刻时需固定一种。**但 VXL 主头内嵌的 768 字节调色板已是 8-bit（0–255）**——实测 `YAGGUN.VXL` 索引 15/20/13 = 255/195/87，而 `UNITURB.PAL` 同索引为 63/48/21（×4 后 = 252/192/84），故体素渲染直接取内嵌值，不可再 `<<2`（否则整模过曝）。原版「法线·光方向 → 具体调色板索引」的阴影映射与「32 级明暗」的精确斜坡表未公开/未多源确认，**待验证**。
